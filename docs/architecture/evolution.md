# Self-Improvement & Self-Reference (Phase 2 — model only)

**Status:** CONCEPTUAL | Autonomy forbidden by default (P11, INV-004).
Basis: EVD-018 (GEPA strong with metric; DGM sandboxed-only + oversight).

## Gated pipeline (§17 — the ONLY permitted improvement path)

```text
Observation → Proposal → Evidence → Experiment → Evaluation → Approval → Versioned Change
```

```text
.eidos/evolution/
├── proposals/    (AGENT_PROPOSED, with evidence refs)
├── experiments/  (EXP-scoped runs, sandboxed)
├── accepted/     (human-approved, versioned, reversible)
└── rejected/     (with reasons, preserved for audit)
```

## Terminology (§17 distinction — never synonyms)

```text
Self-Reflection — verbal failure summary into episodic memory (no fix guaranteed)
Self-Repair — bounded retry of the SAME task with oracle feedback (convergent)
Self-Improvement — updating model/prompts/pipeline from curated data + metric (needs validator)
Self-Evolution — modifying the mechanism/search space itself (divergent in principle;
  DGM/Gödel lineage; FORBIDDEN outside sandbox + human approval until EXP-006)
```

Eidos permits Reflection + bounded Repair now (architecture), GEPA-style
Improvement as EXPERIMENTAL (EXP-006), Evolution as PROHIBITED-by-default.

## Self-reference (§18 — proposed property, NOT validated capability)

```text
Eidos → Analyzes Eidos → Plans Change → Executes → Verifies → Records Evidence → Updates Eidos
```

Axiom 0 (self-hosting) is retained as architectural direction: every Eidos phase
dogfoods the previous baseline inside the primary harness. Validation of the full
cycle belongs to Phases 6–8, not Phase 2. No claim of recursive self-improvement
is made or implied.
